# Video Service 测试问题修复说明

## 📋 问题分析

### 失败原因

测试失败的根本原因是 **`file://` 协议处理不当**：

```
错误信息: "File not found: file:///test-data/video-service/scene_1.jpg"
```

### 问题详情

1. **代码缺陷位置**: `backend/video-service/app/services/local_storage_client.py:45-48`

2. **原始代码**:
   ```python
   else:
       if os.path.exists(url_or_path):
           shutil.copy2(url_or_path, local_path)
       else:
           raise FileNotFoundError(f"File not found: {url_or_path}")
   ```

3. **问题**: 
   - 当 `url_or_path` 是 `file:///test-data/video-service/scene_1.jpg` 时
   - `os.path.exists()` 会检查路径 `file:///test-data/video-service/scene_1.jpg`
   - 这个路径包含 `file://` 协议前缀，导致检查失败
   - 实际文件路径应该是 `/test-data/video-service/scene_1.jpg`

### 证据

从测试日志可以看到：
```bash
# 容器内文件确实存在
$ docker exec video-service ls -lh /test-data/video-service/
-rw-r--r-- 1 1000 1000  31K Oct 25 13:22 scene_1.jpg  # ✅ 文件存在
-rw-r--r-- 1 root root  72K Oct 25 13:26 scene_1_audio.mp3  # ✅ 文件存在

# 但任务仍然失败
"error": "File not found: file:///test-data/video-service/scene_1.jpg"
```

---

## 🔧 修复方案

### 修复内容

修改 `backend/video-service/app/services/local_storage_client.py`，添加 `file://` 协议处理：

```python
async def download_file(self, url_or_path: str, local_path: str):
    """
    从本地路径或URL下载文件
    
    Args:
        url_or_path: 源文件路径或URL
        local_path: 目标本地路径
    """
    if url_or_path.startswith('http://') or url_or_path.startswith('https://'):
        async with httpx.AsyncClient(timeout=300) as client:
            response = await client.get(url_or_path)
            response.raise_for_status()
            
            with open(local_path, 'wb') as f:
                f.write(response.content)
    else:
        # ✨ 新增：处理 file:// 协议
        file_path = url_or_path
        if url_or_path.startswith('file://'):
            file_path = url_or_path[7:]  # 移除 'file://' 前缀
        
        if os.path.exists(file_path):
            shutil.copy2(file_path, local_path)
        else:
            raise FileNotFoundError(f"File not found: {url_or_path}")
```

### 修复效果

- ✅ 支持 `http://` 和 `https://` URL
- ✅ 支持 `file://` 协议的本地路径
- ✅ 支持不带协议前缀的本地路径
- ✅ 保持向后兼容

## 🎵 音频文件生成

### 问题

原始测试数据中音频文件使用 MP3 格式，需要 FFmpeg 生成。但：
- 主机可能没有安装 FFmpeg
- 容器内已有 FFmpeg，但在主机生成更方便

### 解决方案

提供 **两种** 音频生成方式：

#### 方式 1: 使用 FFmpeg（推荐，生成 MP3）

```bash
cd test-data/video-service
./generate_audio.sh
```

**优点**: 
- 生成 MP3 格式，文件小
- 音质好

**缺点**: 
- 需要主机安装 FFmpeg

#### 方式 2: 使用 Python（备用，生成 WAV）

```bash
cd test-data/video-service
python3 generate_audio.py
```

**优点**: 
- 不依赖 FFmpeg
- 纯 Python 实现

**缺点**: 
- 生成 WAV 格式，文件较大
- 需要修改 test_request.json 中的音频文件扩展名

**注意**: 本次修复已将 `test_request.json` 更新为使用 WAV 格式，确保在没有 FFmpeg 的环境也能测试。

### 问题 2: 容器内看不到 WAV 文件

**症状**: `docker exec video-service ls /test-data/video-service/` 没有 WAV 文件

**原因**: 
1. 卷挂载配置可能未生效
2. 音频文件生成失败

**解决方案**:
```bash
# 1. 确认音频文件已在主机生成

cd backend/video-service

# 3. 再次验证
docker exec video-service ls -lh /test-data/video-service/*.wav
```

---

### 问题 3: 测试仍然报 "File not found"

**症状**: 任务失败，错误信息包含 "File not found: file://..."

**可能原因**:
1. 代码未重新构建
2. 容器使用了缓存的旧镜像

**解决方案**:
```bash
# 完全清理并重建
cd backend/video-service
docker-compose down -v
docker-compose build --no-cache
docker-compose up -d

# 等待服务启动
sleep 10

# 验证代码修复已生效
docker exec video-service grep -A 3 "file_path = url_or_path" /app/app/services/local_storage_client.py
```

应该看到新增的代码：
```python
file_path = url_or_path
if url_or_path.startswith('file://'):
    file_path = url_or_path[7:]
```

### 问题 4: Celery Worker 未处理任务
